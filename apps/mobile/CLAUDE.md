# apps/mobile — Expo Router + React Query + GraphQL

Loaded when working under `apps/mobile`. The cross-cutting conventions are in the root `CLAUDE.md`.

## Structure

- **Routing:** Expo Router, file-based under `app/`.
  - `app/_layout.tsx` waits for auth to restore, then picks `(app)` or `(auth)` with `Stack.Protected`.
  - `(auth)` holds `login` and `register`.
  - `(app)` holds `index` (the applications list); `applications/new`, `[id]`, `[id]/edit`, `[id]/notes`, `[id]/cover-letters`, `[id]/resumes`, `[id]/other-documents` (one screen per document category, JEF-396), `[id]/documents/[draftId]` (the draft editor) and `trash`; `conversations` and `conversations/[id]` (`id` is `new` for an unsaved thread); and `settings/{profile,security,notifications,ai}`.
- **Route files are thin re-exports** of screens in `src/features/*/screens/` or `src/screens/`. Screens use `expo-router` hooks directly rather than navigation props. Static titles are set in `(app)/_layout.tsx`; only screens that need runtime data, such as `ApplicationsListScreen`, set `<Stack.Screen options>` inline.
- **No path alias:** imports are relative (`../src/...` from `app/`).

## Auth transport

- **Tokens:** the `*Mobile` mutations return both tokens in the body. The pair is stored as **one JSON value under one SecureStore key** (`src/auth/tokenStorage.ts`) so it can't be half-updated, which the API would read as refresh-token reuse. The access token is also held in memory.
- **Refresh:** `gqlRequest` (`src/graphql/client.ts`) refreshes once and retries on `UNAUTHORIZED`, but only if the request carried a token.
  - Pass `{ refreshOnUnauthorized: false }` where `UNAUTHORIZED` means "wrong password" (`updatePassword`, `reauthenticateMobile`).
  - A refresh that can't reach the server keeps the tokens. Only a rejected refresh token ends the session, and ending it (like sign-out) clears the React Query cache.
- **Non-GraphQL callers** (the chat SSE stream) use `getValidAccessToken()` and `recoverFromUnauthorized()`.
- **User-Agent:** `TrakwynMobile/<version> (<model>; <os>)`, which the API turns into the session label and records on its request spans as `app.client.version`, `device.model.name`, `os.name` and `os.version`. Change the format only together with `apps/api/src/infrastructure/device/trakwynClientUserAgent.ts`.
- **Step-up:** `STEP_UP_REQUIRED` is handled by `src/auth/useStepUpReauth.tsx` (the one hook; the settings-level copy is gone). Before the prompt opens it reads `me.stepUpMethods` (`src/auth/stepUp.ts`): a password account gets the password prompt (`reauthenticateMobile`), one without a password gets `StepUpWithoutPasswordPrompt` (JEF-463): Google through the in-app browser (`startOAuthReauth` ticket, then `/start?mode=reauth&platform=mobile`, then the usual handoff code) and/or a mailed code (`verifyStepUpCodeMobile`). Both go through `AuthContext`'s `reauthenticateWithProvider`/`verifyStepUpCode`, which store the session's refreshed tokens **without** the sign-in's cache reset.
- **`PLAN_REQUIRED` (JEF-344):** `getErrorMessage` keeps the API's message, which names the Pro feature, and adds "Manage your plan on the web." There is no in-app purchase, so every screen that shows an error gets that state with no per-screen code.
- **`expo start --web` is a dev preview only.** It keeps tokens in `localStorage`; shipping it would first require switching to the cookie mutations.

## Email verification wall (JEF-438)

`app/(app)/_layout.tsx` renders `VerifyEmailRequiredScreen` (`src/features/verification/`) instead of the tabs while `me.emailVerified` is false, and `AccountDeletionScheduledScreen` (cancel or sign out) while `me.deletionScheduledAt` is set (JEF-463); the API refuses everything else for such an account. Danger Zone only _requests_ deletion (type the email, step up, a link is mailed); the confirm and cancel links open the web app. Same rules as web: the app shows while the check is in flight or fails (the API enforces the wall), resend has a 60 s cooldown, and "Use a different email" reuses `useRequestEmailChange`. There is no window focus on a phone, so the check reruns when the app returns to the foreground.

## Resume and cover letter editor (JEF-508)

Create new on the Resumes and Cover letters screens (`useCreateOrOpenDraft`) opens the editor at once and reuses the application's blank draft of that type instead of adding another (the list query selects `plainText` for this). There is no New resume or New cover letter screen. The editor edits plain text with Markdown markers, so Replace and Insert below write the polished Markdown as text.

- **AI helper:** a bottom sheet (`AiHelperSheet`) opened from the editor header. `useDraftAiHelper` runs `generateIntoDocumentDraft` (empty editor) and `polishDocumentDraft` (text in the editor); neither saves, the editor saves through `useDraftSaver`. Polish is a suggestion held until Replace or Insert below. Replace is refused when the text changed since the suggestion was made.
- **Never overwrite edits:** the editor is read-only while a request runs. Saves are serialised, and a failed one keeps its payload for the Retry button. The debounced autosave reads the text when it fires, not when it was scheduled.
- **Credits:** `useAiCredits` reads the `llmApiKeys` query (`me.aiCredits.costs`, `me.aiProviderOrder`). The cost and credits-left lines show only when Trakwyn AI answers. Never copy the weights into the app.
- The old `generateResume` and `generateCoverLetter` mutations are still on the API for older app versions, but this app no longer calls them.

## Content quotas (JEF-494)

Same behaviour as web (`apps/web/CLAUDE.md`): `features/quota/` has the hand-written `ContentQuota` document, `useQuotaState`/`useQuotaFull` and `QuotaHint`, which stays silent below 80%. Each capped screen passes the length of the list it already holds, and `FloatingActionButton` takes `disabled` at the cap. The create errors already go through `getErrorMessage`, so a lost race shows the API's message. Call `useQuotaFull` above any early return (`rules-of-hooks`), and stub `features/quota/hooks/useQuotaState` in a screen test that has no query client. The `ContentQuota` document is checked by `graphqlDocuments.test.ts`.

## Error reporting (JEF-349)

The same rules as web (`apps/web/src/lib/analytics/CLAUDE.md`), with these differences:

- **Off by default:** nothing is sent without `EXPO_PUBLIC_POSTHOG_KEY`.
- **No autocapture:** `<PostHogProvider autocapture>` is not mounted.
- **Scrubber:** `lib/analytics/scrub.ts` is kept in parity with web's copy.
- **No consent gate:** there is no banner in a native app; the scrubber is what makes that acceptable.
- **Native crashes** are captured by `@posthog/react-native-plugin`. It is a **plain dependency, not an Expo config plugin**, and adding it to `app.json` `plugins` breaks `expo start`. It works only in dev/EAS builds, not Expo Go.
- **Release health (JEF-368):** crash-free sessions and users per app version and release are a PostHog dashboard in `infra/posthog` (`release_health.tf`). A crash is a `fatal` `$exception`, a session a `$session_id`. Keep `captureAppLifecycleEvents`, `nativeCrashes` and the `release` super property: the dashboard depends on them.
- **GraphQL transport failures (JEF-370):** `gqlRequest` reports its _final_ failure (after any refresh-and-retry) as `graphql_request_failed` with `status` or `network_error: true`, `operation` and `trace_id`. The operation name is parsed from the query string by `operationName` (`graphql/requestTimeout.ts`, shared with the timeout breadcrumb), and a timeout reports as `network_error`. Which failures qualify (5xx and no response; never 4xx or domain codes) is `lib/analytics/transportFailure.ts`, mirrored from web and held identical by web's `transportFailureParity.test.ts`. Each attempt mints its own `traceparent`, so `trace_id` is the failing request's rather than the shared last-trace id; `addTraceparent` keeps a `traceparent` the caller already set. The refresh call itself is not reported here: it has its own events.
- **Breadcrumbs** (`addBreadcrumb`) cover token refresh, SecureStore failures, chat-stream reopens and navigation. Navigation is recorded with `useSegments()` (e.g. `/(app)/applications/[id]`), never `usePathname()`, so no identifiers leak.
- **Network context (JEF-367):** `NetworkBreadcrumbs` records NetInfo's `connected`/`reachable`/`type` on change only, never `details` (SSID, IP, carrier), and feeds `$network_connected` on every event. `gqlRequest` and the token refresh time out after `GQL_REQUEST_TIMEOUT_MS` with a `RequestTimeoutError` (a `TypeError`, so it reads as a network failure). `chatStream.ts` breadcrumbs error frames (code only), a close before `done` and a mid-reply drop, with elapsed time and whether text had arrived.
- **App lifecycle (JEF-369):** `Application Opened`/`Backgrounded`/`Installed`/`Updated` come from `captureAppLifecycleEvents`.
  - **Cold start:** `app_started` is sent once per process by `reportAppStarted` (`lib/analytics/startupTiming.ts`) when the root navigator first resolves auth. It carries `duration_ms`, `outcome` (`signed_in`/`signed_out`) and `start_marker`. RN's `performance.now()` counts from _system boot_, so neither it nor `performance.timeOrigin` is a duration on its own. The start is `performance.rnStartupTiming.startTime` (`start_marker: 'native'`), falling back to when the module was evaluated (`'js_module'`, which undercounts).
  - **JS hangs:** `<HangWatchdog>` runs `startHangWatchdog` (`lib/analytics/hangWatchdog.ts`) while in the foreground. A tick late by `HANG_BREADCRUMB_MS` leaves a breadcrumb, and one late by `APP_HANG_THRESHOLD_MS` is captured as `JS thread blocked` with `kind: 'app_hang'`, `blocked_ms` and the `useSegments()` route. Only the first hang per process is captured. It is stopped in the background, where suspended timers would read as a hang, and a gap over `HANG_MAX_PLAUSIBLE_MS` is discarded as a suspension in case the AppState event missed the freeze.
  - **Native ANRs are a known gap.** `@posthog/react-native-plugin` 2.9.x only turns on the native SDKs' crash autocapture: uncaught exceptions on Android, crash signals on iOS. An Android ANR is not an exception, and an iOS watchdog termination is a `SIGKILL` that cannot be caught in-process, so neither is reported. A JS-thread block, the usual cause in this app, is covered by the watchdog. A main-thread (native) block is not. Revisit if PostHog adds ANR detection rather than adding a second SDK.
  - **OTA update outcomes are deferred.** `expo-updates` is not installed, pending the build and update strategy in JEF-300. When it is added, report `Updates.updateId` and `isEmbeddedLaunch`, send `ota_update_failed` for `checkForUpdateAsync`/`fetchUpdateAsync` failures and for `Updates.isEmergencyLaunch`, and register `updateId` beside `release` as a super property.

## Testing (JEF-300)

four tiers, three of them Jest projects declared in `apps/mobile/jest.config.js` and separated by where a suite already lives, so nothing was renamed to create them. `unit` is every `*.test.ts` under a `__tests__` directory (pure logic, no renderer); `component` is every `*.test.tsx` (a screen or hook through `@testing-library/react-native`); `integration` is `src/__integration__/`, which boots `apps/api` from `globalSetup` and talks to it for real. `pnpm test` runs the first two, `test:unit`/`test:component`/`test:integration` run one each, and `test:e2e` runs the Maestro flows in `.maestro/` against a build on a device. `src/__tests__/architecture/tierAssignment.test.ts` asks Jest itself (`--listTests`) which files the next CI run will execute and fails if one belongs to no project — a suite matched by nothing does not fail, it silently stops running. Two things the integration tier exists for: mobile hand-writes its 96 GraphQL documents with no codegen, so `graphqlDocuments.test.ts` validates every one against the live schema (it found `DeleteOffer` declaring `$id: ID!` against a `String!` argument — a mutation that could never have succeeded); and every other suite replaces the transport, so `authRoundTrip.test.tsx` is the only place the auth header, the `User-Agent` the API turns into a session label, and the refresh-and-retry path meet a real server. That tier needs Node's own `fetch`: jest-expo installs Expo's, whose native module is stubbed under Jest, so `src/__integration__/nodeFetchEnvironment.js` hands the sandbox the real one. `src/__tests__/setupAfterEnv.ts` gives every tier a React Query client whose `gcTime` is `Infinity` (no gc timer is armed at all — `0` is not equivalent: it arms a 0 ms eviction that races `act` and empties the cache a mutation test just asserted on) and a synchronous notify scheduler — without them each rendered screen leaves a five-minute gc timer armed, which is what "a worker process has failed to exit gracefully" was. `src/__tests__/architecture/maestroTestIds.test.ts` resolves every `id:` the Maestro flows select against the `testID`s the app declares, so a screen rework that drops one fails at the Jest tier rather than on the emulator; a `testID` on a `<Text>` nested inside another `<Text>` passes that check and is still unfindable on Android (see `.maestro/README.md`).
