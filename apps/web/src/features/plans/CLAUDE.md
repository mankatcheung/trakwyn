# Plans and locked previews (JEF-344)

Loaded when working under `apps/web/src/features/plans`. The rest of the web notes are in `apps/web/CLAUDE.md`. Paths are relative to `apps/web/src/` unless stated.

- **`PLAN_REQUIRED` is an upgrade prompt, not a failure.** `ErrorState` and `AiErrorMessage` branch on it, and the forms that can hit it (new application at the cap, share link) render `UpgradePrompt`. The text is the API's own message, which names the feature; the link goes to **Settings → Plan**.
- **`useBillingStatus()`** (`features/plans/lib/billingStatus.ts`) is the one reader of `billingStatus`. Settings → Plan shows the plan, usage against each limit and a Free/Pro comparison built from the API's `catalogue`, so no limit is copied into the web app. Buying Pro arrives with billing (JEF-426).
- **Locked previews (JEF-523).** `LockedFeaturePreview` (`features/plans/components/`) replaces a Pro-only section for a Free user: a blurred, fictional sample, an "Available on Pro" badge and a link to Settings → Plan, which fires `upgrade_clicked {source: 'locked_preview', feature}`. It is shown only when `useFeatureLocked(feature)` is true, i.e. `billingStatus.features[feature]` is `false`, so it never shows while status loads or where plans are not enforced. The Offers page uses the card. Analytics uses `LockedFeatureOverlay`, which covers the whole page: `LockedAnalyticsSample` (fictional numbers, blurred, `inert`) with one sticky message card over it, so none of the user's real figures sit beside the lock and the gated queries never fire. `notifications` is deliberately not previewed: the API exposes the flag but gates nothing on it, so Free users still get reminders. `ApplicationCapNotice` (applications list) is the soft heads-up between 80% of the application limit and the cap, read from `billingStatus`, not `contentQuota`.
