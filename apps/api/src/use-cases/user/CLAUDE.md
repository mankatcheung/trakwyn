# apps/api/src/use-cases/user - subsystem notes

Loaded when working under `apps/api/src/use-cases/user`. The rest of the API notes are in `apps/api/CLAUDE.md` and the layer map is in the root `CLAUDE.md`. Paths below are relative to `apps/api/src/` unless stated.

## AI provider order

Which AI answers is an ordered list the user saves, not three settings. It replaces the source, the default key and the fall-through toggle, which each said part of it.

- **State.** `User.aiProviderOrder` is a nullable `text[]`: `trakwyn` (`AI_PROVIDER_ORDER.TRAKWYN`) and/or the ids of the user's own keys, first to last. **Null means the user never saved one**, and `effectiveAiProviderOrder` (`use-cases/shared/aiProviderOrder.ts`, pure) derives the order from what the older fields already meant, so nobody's behaviour changed when it arrived and there is no data backfill: `trakwyn` is the platform alone; `own` is the default key (the oldest key if the default was deleted), then the other keys oldest first only when `llmFallbackWhenLimited` is on; `auto` is the same own-key chain, or the platform alone when there is no key and `canAutoUseTrakwyn` (hosted AI on for them and a paid plan). The migration is one additive column.
- **Resolution.** `LimitEnforcingLLMProviderFactory.resolveOrdered` walks the order. An entry is skipped when its key is gone, hosted AI is off for the user, the key is paused at its monthly limit, or the platform refuses for credits, plan, rate or the daily breaker (`isSkippable`). Anything else, an unverified email above all, stops the call: another provider does not fix it. If every entry is skipped the **first** entry's own error is thrown, so a single paused key still reads "limit reached". **A provider that is not listed is never used**, and Trakwyn AI is never reached for by a user who listed only keys; `LimitEnforcingLLMProviderFactory.order.test.ts` pins that. The inner factory is told the path with `hints.via` (`platform` or `key`) so the order, not `aiSource`, decides.
- **Credits are charged on the resolution's source for whichever entry produced it** (`chargeCredits`), inside the walk, so an exhausted balance falls through to the next entry instead of failing the call.
- **A call that names a key, and a key test, keep the single-key path** (`resolveKey`). Nothing in the app names a key on a tracked call any more: chat used to, and no longer does.
- **While the call runs.** When the entry that is answering fails with `rate_limited`, `unavailable`, `unreachable`, `auth` or `quota` (not `bad_request`: the next provider would refuse it too), `OrderedFallbackLLMProvider` moves to the next entry. Never after the caller has been handed an event, never on a cancelled call. The next entry is resolved **lazily**, so a provider further down the order costs nothing, and takes no credits, unless it is used. The switch is sticky for the life of the resolution (a chat turn calls the provider once per tool round) and is told to the caller as a `fallback` stream event (`LLMStreamEvent`), which the chat use case forwards and the clients show. `LLMProviderResolution.entry` is the entry that answers and `fellBackFrom` the first one skipped before the call; both are entry names (`trakwyn` or a key id), unlike `providerId`, which is the provider behind the call.
- **Chat is not locked to a key.** `StreamChatWithAssistantUseCase` asks for a provider with no key and no model, so the order decides every turn. `Conversation.llmProvider` is still stamped once, with the key that answered first, and only when that was one of the user's own keys; it is a record of where the chat started, not a setting, and clients show what the order says now.
- **Setting it.** `setAiProviderOrder(order)` (`SetAiProviderOrderUseCase`) refuses an empty list, a repeat, a key the user has not saved, and `trakwyn` while hosted AI is off for them. It does not check the plan: a Free user who lists Trakwyn AI is refused at call time with `PLAN_REQUIRED` and falls through. `me.aiProviderOrder` (`GetAiProviderOrderUseCase`) is the saved or derived order **minus what could not run today**, so the settings page never promises a provider the call would skip.
- **The older settings still work, for apps in the stores (JEF-417).** `setAiSource`, `setDefaultLlmProvider` and `updateProfile(llmFallbackWhenLimited)` are deprecated but unchanged for an older client, and each **clears a saved order** (sets it to null) so the setting that was just changed is the one in force. Deleting a key removes it from a saved order, and an order left empty goes back to null. Remove the deprecated fields and mutations only once the versions that use them are out of use (`Client compatibility` in `apps/api/CLAUDE.md`).
- **Not done:** a per-provider monthly credit or spend cap, and a "reset to automatic" action.
