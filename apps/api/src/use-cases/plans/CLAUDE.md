# apps/api/src/use-cases/plans - subsystem notes

Loaded when working under `apps/api/src/use-cases/plans`. The rest of the API notes are in `apps/api/CLAUDE.md` and the layer map is in the root `CLAUDE.md`. Paths below are relative to `apps/api/src/` unless stated.

## Plans and entitlements

Free and Pro. This is the tiering half; taking payment is JEF-426 (see `infrastructure/billing/CLAUDE.md`), which sets the same user fields from a provider's webhook.

- **State vs policy.** The user row holds only `plan` (`free`/`pro`), `planExpiresAt` and `planSource` (`subscription`, `pass`, `trial`, `grant`). What a plan allows is code: `PLAN_LIMITS` and `PLAN_FEATURES` in `use-cases/constants.ts`, whose Free column _is_ `CONTENT_LIMITS`. `resolveEntitlements(plan, planExpiresAt, now)` (`use-cases/plans/`) is pure, and `effectivePlan` (domain) reads an expired pass or trial as Free, so nothing has to run to downgrade a user. Data is never touched by a downgrade: a user over a cap can read, export and delete, not add.
- **`PLANS_ENFORCED` (default off) is read in one place**, `EntitlementService`. Not enforced means every Pro feature on, **but the caps that already existed stay** (50 applications, 100 MB): lifting them would loosen a deployed system the moment this shipped. Every self-hosted instance runs this way. No use case checks the flag.
- **Gating is `entitlementService.assertFeature(userId, feature)` as the first line of a use case** (`PlanFeature`: `notifications`, `analytics`, `offers`, `shareLinks`, `apiAccess`, `mcpAccess`). It throws `PlanRequiredError` (`PLAN_REQUIRED`, 403 through `fromCodedError`). Gated: the offer and analytics aggregates and `CreateOfferUseCase`, `CreateShareLinkUseCase`. Reading your own data stays open (per-application offers, export). `featureGating.test.ts` asserts each refuses before touching any other dependency, so a new gated use case gets a row there.
- **Jobs skip, they do not fail.** The digest, reminder and push jobs skip a Free user (counted as `skipped`) without sending, without creating an inbox row and without marking a round notified, so an upgrade before it passes still gets it.
- **MCP is on for every plan; the GraphQL API with a token is Pro (JEF-442).** `mcpAccess` is true in both `PLAN_FEATURES` columns and `apiAccess` only in Pro. Any plan may create an API token (`CreateApiTokenUseCase` is not gated). `ValidateApiTokenUseCase.execute(rawToken, surface)` checks the feature of the surface it is serving: `'mcp'` needs `mcpAccess` (`AuthenticateMcpRequestUseCase`, for API tokens and the OAuth branch), `'graphql'` needs `apiAccess` (`AuthenticateRequestUseCase`). So a Free user's token works on `/mcp` and is refused on GraphQL, and it is not deleted, so an upgrade brings the GraphQL side back.
- **AI actions are not limited by plan (JEF-442).** They run on the user's own key, which the provider bills directly, so neither plan has an allowance; the only AI limit is a key's own `monthlyTokenLimit` (JEF-258) in `LimitEnforcingLLMProviderFactory`. There is no `aiActionsPerMonth` limit or `aiActionsThisMonth` usage any more. Trakwyn AI (JEF-446, `infrastructure/llm/CLAUDE.md`) runs on a key Trakwyn pays for and has no allowance yet; that is Hosted AI 4.
- **Caps are passed in, not read.** `CreateApplicationData.applicationLimit` (`null` = none) and `CreateDocumentData.storageLimitBytes` come from the owner's entitlements, and the repositories still reserve against them in one conditional `UPDATE`. A new caller of either `create` must pass one. The per-parent counts follow the same rule (JEF-440): `CreateDocumentData.documentsPerApplicationLimit`, `CreateInterviewQuestionData.questionsPerRoundLimit` and `CreateMockInterviewQuestionData.mockQuestionsPerRoundLimit` are passed by the create use cases from `CONTENT_LIMITS` (they do not vary by plan), and no repository reads `CONTENT_LIMITS` for a cap.
- **`billingStatus`** (`GetBillingStatusUseCase`) returns the plan, `enforced`, the user's features, limits and usage, and a `catalogue` of both plans so a client can compare them without copying the numbers. `me.storageLimitBytes` follows the plan.
- **The user row is cached** (`CachedUserRepository`, five minutes). The repositories bust it on create/delete of an application and a document, and on `update`. A change made by the operator command goes around the cache, so it shows within five minutes.
- **Operator command:** `pnpm --filter @trakwyn/api plan set --email <email> --plan <free|pro> [--days <n>]` records a `grant`; `plan grant-trial [--days <n>] [--dry-run]` gives every user who has never had a plan a Pro `trial` (30 days by default, `PLAN_TRIAL.LAUNCH_DAYS`), so it is run on the day enforcement is switched on, not in a migration, and a second run grants nothing twice. Both write to `DATABASE_URL` directly (`src/plan.ts`).
- **Launch order:** ship with enforcement off, build payment (JEF-426), then set `PLANS_ENFORCED=true` and run `plan grant-trial`.

## Hosted AI credits

A monthly budget for calls on the platform's key. Own-key calls and key tests are never charged.

- **Policy** is `AI_CREDITS` (`WEIGHTS` per `AI_FEATURE`, typed `satisfies Record<AiFeature, number>` so a new feature must be weighed; `WELCOME_BONUS` 20 for `WELCOME_DAYS` 14), `PLAN_LIMITS.<plan>.aiCreditsPerMonth` (**Free 0, Pro 300**: hosted AI is Pro-only in phase 1, JEF-451) and `PLAN_TRIAL.AI_CREDITS` (100). `resolveEntitlements` takes the plan source and uses the trial size for a Pro `trial`. `talkingPoints` and `parseCv` weigh 1; the ticket did not list them.
- **Pro-only for now (JEF-451).** Free has 0 credits and no welcome bonus (`welcomeBonus` is 0 for a plan with no credits). A Free user with source `auto` and no key never reaches the platform: `UserLLMProviderFactory` returns no provider, so they get `AI_NOT_CONFIGURED` as before hosted AI. A Free user forced onto `trakwyn` (a downgrade, or a stored setting) is refused by `AiCreditService.charge` with `PLAN_REQUIRED` and an upgrade message, not `AI_CREDITS_EXHAUSTED`. The non-fair-use `AiCreditsExhaustedError` is therefore unreachable until Free credits return; its wording stays pinned by a test. To turn Free credits back on, set `PLAN_LIMITS.free.aiCreditsPerMonth`, and remove the `isPaid` gate in `UserLLMProviderFactory` and the zero-credit refusal in `AiCreditService.charge`.
- **The exception to "not enforced means everything on":** `EntitlementService`'s unenforced entitlements give the **Free** size of credits, not Pro's, because hosted AI costs real money. With Free at 0 that means no hosted AI on an unenforced instance.
- **Counter on the user row:** `aiCreditsUsed` and `aiCreditsPeriodStart` (the UTC month it counts). `reserveAiCredits(userId, credits, limit, periodStart)` is one conditional `UPDATE` that restarts the counter when `periodStart` is newer and refuses past `limit`, so there is no reset job and two reserves at 29/30 cannot both pass. `releaseAiCredits` refunds, only within the same period. Both bust the cached user row. Read the counter through `AiCreditService.standing`, never raw: it is stale after the month turns. No rollover.
- **Charging** is `LimitEnforcingLLMProviderFactory.resolveForUser`, after the inner resolution and only when `source === 'platform'` and `trackUsage !== false`: `IAiCreditService.charge` reserves the feature's weight (the limit includes the welcome bonus while it lasts) or throws `AiCreditsExhaustedError` (`AI_CREDITS_EXHAUSTED`, 403, `limit`, `resetsAt`). A chat turn resolves once, so it is one charge.
- **Refund:** `CreditRefundingLLMProvider` wraps the provider and refunds once if a call fails with `LlmProviderError` before **any** call of that resolution has returned or streamed an event. A success, a partly streamed answer or a cancelled call keeps the credits.
- **Past the credits (JEF-448).** A Free user is refused as above. A Pro user is let through as `overflow` (nothing reserved) until the month's platform spend reaches `AI_COST_CEILING_MICROS.pro` (1_500_000 micro-USD), then refused with `AiCreditsExhaustedError(…, fairUse = true)`, whose message names no amount. The ceiling is read only in the overflow branch (`ILlmUsageEventRepository.sumCostMicros(userId, monthStart, 'platform')`, the primary database) and a failed read throws, so it fails closed. A call whose model has no entry in `LLM_PRICES` records `costMicros` null and adds nothing to that sum, so a new platform model needs a price.
- **Exposure:** `billingStatus.aiCredits { used, limit, bonusRemaining, resetsAt }`, `billingStatus.limits/catalogue.aiCreditsPerMonth`, and `me.aiCredits`. `limit` is the plan's size without the bonus; `bonusRemaining` is what is left above it.
