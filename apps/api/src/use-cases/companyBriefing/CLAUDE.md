# apps/api/src/use-cases/companyBriefing - subsystem notes

Loaded when working under `apps/api/src/use-cases/companyBriefing`. The rest of the API notes are in `apps/api/CLAUDE.md` and the layer map is in the root `CLAUDE.md`. Paths below are relative to `apps/api/src/` unless stated.

## Company site research (JEF-475)

A briefing used to rest on the model's memory alone, so for a company it did not know it was generic. `GenerateCompanyBriefingUseCase` now reads what the company says about itself first, hands those pages to the model as numbered, fenced data, and saves the pages it used as the briefing's `sources`.

- **Port and adapters.** `ICompanyResearchSource.research({ company, jobUrl })` returns `{ pages }` or `null` (`use-cases/ports/`). `FetchCompanySiteResearchSource` (`infrastructure/companyResearch/`) is the only implementation; `CachedCompanyResearchSource` wraps it in `http/di/infrastructure.ts` (`companyResearchSource`, `asFunction` because the decorator's `inner` is not a registration). The paid search (below) is a second implementation behind the same port.
- **Which site.** `companySiteOrigin(jobUrl)` takes the posting link's host, drops a hiring subdomain (`careers.`, `jobs.`, `www.` …, `COMPANY_RESEARCH.HIRING_SUBDOMAINS`) and returns `https://<host>`, or `null` for no link, a non-web scheme, a bare hostname, or a job board (`COMPANY_RESEARCH.JOB_BOARD_HOSTS`, matched on the host or a parent). A job board hosts many companies, so its link says nothing about this one. With no usable link there is no research and the briefing is written as before. Only the host is kept: the path and query of a posting link never reach the company's server. The root and the first of `ABOUT_PATHS` that answers with text are the only requests.
- **Outbound fetch rules** are the job-posting ones: every request and redirect hop goes through `IOutboundUrlPolicy` with purpose `company-research`, redirects are followed by hand (`MAX_REDIRECTS`), the body is read with `readBounded` (`MAX_BYTES`), and only `text/html` is kept. Text is made by `htmlToText`, preferring a `<main>` with real content, and cut at `MAX_CHARS_PER_PAGE`. A page under `MIN_PAGE_CHARS` is a script-rendered shell and is skipped.
- **Never fatal.** The adapter swallows a refused URL, a timeout or a bad page per page and answers `null` when none is left; the use case also treats a throwing source as "nothing read". An unreachable site never costs the user a briefing.
- **Shared between users.** The cache is keyed `company-research:<VERSION>:<host>` for `COMPANY_RESEARCH.TTL_MS` (a week), so the host alone is the key and nothing about one user's application is visible to another. `getOrSet` single-flights. An empty answer is deleted straight after, so a site that was down for a minute is retried by the next briefing instead of being remembered as having no pages. **Bump `COMPANY_RESEARCH.VERSION` when what is read or how it is cleaned changes.**
- **Budget and the sources list.** `fitResearch` keeps pages in order until `AI_PROMPT_INPUT.COMPANY_BRIEFING_RESEARCH_MAX_CHARS`. The same fitted list is numbered in the prompt and saved, so a source is never listed that the model did not see. Only `url` and `title` are saved (`CompanyBriefing.sources`, a `jsonb` column with a default of `[]`); the page text is not kept.
- **Prompt.** `companyBriefingPrompt` (version 5) fences the sources with `wrapUntrustedContent`, tells the model to cite `[n]` after each claim drawn from them, to say so when a section is not covered, and to leave out time-sensitive claims (funding, layoffs, leadership) unless a numbered source states them. With no sources it behaves as version 2 did and does not cite. A source is third-party text, so an instruction in one is data: `briefing-ignores-orders-in-a-page` and `briefing-ignores-orders-in-a-search-result` in the evals cover it. Version 4 adds the second kind of source (below). Version 5 (JEF-544) tells it to put notable dated news from a search result about the company (funding, expansion, an acquisition) in the overview, with its date and citation.
- **Evals.** `evals/cases/briefing.ts` runs the real use case against an invented company's pages (`fixtures/briefingFixtures.ts`): grounded, an injection in a page, one page only, and no page, then three with search results (below). The checks are mechanical (cites only pages that were given, uses a fact only the pages hold, leaves out funding the pages never state), not a judge.
- **Clients.** `CompanyBriefing.sources { url title }` is a new field, so an app that never asks for it is unaffected. Web and mobile list them numbered to match the citations and open only `http(s)` addresses. Web's disclaimer says "from the company's own website" only when there are sources.
- **Not done here.** The company's site is not found when the application has no posting link or only a job-board link. Search could find it, but a search result is a page this server would then have to fetch, which is its own review (below).

## Web search (JEF-538)

News, funding, layoffs and reviews, from a search Trakwyn pays for (Tavily), added to the site pages for a Pro user. Everything else about research (never fatal, untrusted, cited) holds for it.

- **Port and adapters.** `IWebSearchProvider.search({ query, topic, maxResults, days? })` (`use-cases/ports/`) returns `{ url, title, snippet, publishedAt }[]`, and throws when the search itself fails. `TavilyWebSearchProvider` and `FakeWebSearchProvider` live in `infrastructure/search/`; `buildWebSearchProvider` picks one from `SEARCH_PROVIDER` (`tavily`, `fake`, or `none`; unset is none, and `tavily` without `TAVILY_API_KEY` is none, so an instance that never set a key sends nothing anywhere). Tavily has no "last N days": `days` becomes `time_range` (`day`/`week`/`month`/`year`), and `include_published_date` is always on. Snippets only: nothing fetches a result's page, so a search result never becomes a server-side request (it would have to go through `IOutboundUrlPolicy` first). JEF-257 (the assistant's `web_search`) should reuse this port.
- **The source.** `SearchCompanyResearchSource` (an `ICompanyResearchSource`) runs a `news` and a `general` search together. Only the cleaned company name (`companyQuery.ts`: one line, no quotes or control characters, so it cannot add operators) and the site host go into a query, never anything about the user or the application, and not the posting link's path. It throws only when both searches fail, so the use case can log `failed` apart from `miss`. Results with a non-web address are dropped.
- **The cache.** `CachedCompanySearchSource` keys `company-search:<VERSION>:<name>:<host|none>` for `COMPANY_SEARCH.TTL_MS` (three days). A job: one search per company per three days, whoever asks. An empty answer and a failure are not kept. **Bump `COMPANY_SEARCH.VERSION` when the queries or the cleaning change.** `companySearchSource` in `http/di/infrastructure.ts` is `null` when there is no provider.
- **Gate and limit, and why neither refuses.** `PLAN_FEATURES.*.companyWebResearch` (Free off, Pro on) is read with `entitlementService.forUserId`, not `assertFeature`: a Free user still gets a briefing, just without search (`apps/api/src/use-cases/plans/CLAUDE.md`). `companyWebSearchRateLimiter` (`RATE_LIMIT.COMPANY_WEB_SEARCH`, 30 a day per user) is spent only after the plan check, so a Free user keeps their allowance, and it is spent on a cache hit too: it limits a user's briefings, not Tavily calls. Past it, search is skipped. On an instance that does not enforce plans every feature is on, so search runs wherever a key is set.
- **Two budgets, one numbering.** `fitResearch` runs on the site pages (`COMPANY_BRIEFING_RESEARCH_MAX_CHARS`) and on the search results (`COMPANY_BRIEFING_SEARCH_MAX_CHARS`) separately, so search never takes the company's own pages' room. The site pages are numbered first and the results follow; the prompt marks each as `kind` `site` or `search`, which only the use case sets (the cached shapes carry no kind). A search result shows `published YYYY-MM-DD` or `date unknown` in the prompt and the model is told to say when a claim was reported and to give a review as opinion.
- **Saved and shown.** `CompanySource.publishedAt` is saved in the same `sources` `jsonb` (no migration; absent for a site page). The API serves it as `null` for a page with no date, and web and mobile show it beside a dated source. The client disclaimer no longer says "the company's own website" since the list can hold both.
- **Observability.** One `Company briefing research` info line per briefing: `sitePages`, `searchPages` and `searchOutcome` (`hit`, `miss`, `failed`, `skipped-plan`, `skipped-limit`, `skipped-unconfigured`). Counts only: no company, query or snippet.
- **Evals.** `briefing-cites-dated-news`, `briefing-ignores-orders-in-a-search-result` and `briefing-ignores-a-search-result-about-another-company`. The mechanical checks cannot tell a model that is right from one that is lucky, so run them against two models before changing the prompt (`evals/CLAUDE.md`).
- **Not done.** Search to find the company's own site, a monthly spend counter (Tavily's own plan cap is the ceiling, `infra/gcp/README.md`, "Web search"), and any fetch of a result's page.
