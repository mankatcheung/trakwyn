# apps/api/src/infrastructure/storage - subsystem notes

Loaded when working under `apps/api/src/infrastructure/storage`. The rest of the API notes are in `apps/api/CLAUDE.md` and the layer map is in the root `CLAUDE.md`. Paths below are relative to `apps/api/src/` unless stated.

## Storage

`STORAGE_PROVIDER` is `local` (disk, dev) or `vercel-blob` (prod). The upload flow is `requestUploadUrl`, then the client uploads directly, then `confirmDocument`.

- Blob returns a client token for `@vercel/blob/client`'s `put()`.
- Local returns a URL under `/uploads/_upload/*` (registered in `buildApp.ts` when `STORAGE_PROVIDER === 'local'`). Web's `DocumentsTab` detects `/_upload/` and `PUT`s to it with `fetch`. `corsPlugin.ts` lists `PUT` explicitly for this.
- **Documents are read through the API, never from a storage URL (JEF-51).** `Document.url` is `GET /documents/:id/file?token=…` (`http/routes/documentFile.routes.ts`), built by `DocumentFileLinkService` behind `IDocumentFileLinks`. The token is `<expiry>.<HMAC>` over the document id and expiry under `JWT_SECRET`, valid for `DOCUMENT_FILE_LINK.TTL_S` (an hour: web reads `url` from a list it may have fetched long before the click), so it opens that one document and nothing else. It carries its own credential because the clients that open it (`<iframe>`, `<img>`, mobile `Linking.openURL`) cannot send one. A resolver only builds a link for a document the caller owns; that is the ownership check, so a new code path that returns a `DocumentDTO` must use `documentFileLinks`, not `getSignedUrl`. The route serves the file through `IStorageProvider.getObject` for both providers. The token is a credential, so it is kept out of telemetry: the http instrumentation's `redactedQueryParams` (`tracing.ts`) blanks it on spans, and `index.ts`'s `req` log serializer blanks it with `redactDocumentToken`. Keep both if either is touched.
- **Server-side readers use `getObject` too** (`ExtractDocumentTextUseCase`, and `ComputeResumeMatchScoreUseCase` and `ComputeResumeAtsScoreUseCase` through `loadDocumentText`, which wraps `readStoredObject` for a bounded read), so they need no URL and keep working when the store becomes private.
- **ATS-readiness score (JEF-395).** `computeResumeAtsScore` scores a resume's extracted text with `scoreResumeText` (`use-cases/shared/`): pure, deterministic, no AI key. The latest result is saved per resume (`ResumeAtsScore`, one row per draft or uploaded file, replaced on a re-check) so it survives a reload; `resumeAtsScores(applicationId)` reads them back with `isStale`, set when a draft's text no longer hashes to `resumeTextHash` (the same rule as the match). Clients must refetch it when a draft is saved. The weights, length range and bands are one `ATS_SCORE` block in `use-cases/constants.ts` and must sum to 100. A scan or image (no extractable text) is `readable: false` with score 0, not a low score, and the other checks are not run. It judges text only, so layout (columns, tables, headers) is not checked. The PDF extractor emits Markdown, so heading and bullet matching tolerate `#`, `**` and `-`.
- **`getSignedUrl` is for avatars only.** They are meant to be seen by other users, so they stay on a public URL. Local read-back is `GET /uploads/*` through `LocalStorageProvider.openObject`, which refuses keys outside `uploads/` and serves only `users/<id>/avatar/…`; every other key is a 404. It is unauthenticated and deliberately not on `IStorageProvider` (JEF-343).
- **Total document storage per user is capped (JEF-425).** `CONTENT_LIMITS.DOCUMENT_STORAGE_LIMIT_BYTES` (100 MB) is counted in `user.documentBytes`, kept transactionally like `applicationCount`: `DrizzleDocumentRepository.create` reserves the bytes with one conditional `UPDATE` (so simultaneous uploads cannot both pass the limit) and throws `QuotaExceededError` with the used and limit values; `delete` releases them; `DrizzleApplicationRepository.delete` releases the sum of the application's documents, because they cascade. Trash counts until it is purged. `requestUploadUrl` takes an optional `sizeBytes` and refuses a full account before the upload; `ConfirmDocumentUseCase` reads the real size with `IStorageProvider.headObject` and refuses a mismatch, so a client cannot under-report. The limit reaches clients as `me.storageUsedBytes`/`storageLimitBytes`, taken from the user's entitlements by `UserMapper`. `DrizzleDocumentRepository.create` takes the limit as `storageLimitBytes`, which `ConfirmDocumentUseCase` and `ExportDocumentDraftToPdfUseCase` read from the owner's entitlements (JEF-344), so a Pro user's 2 GB is enforced by the same one `UPDATE`.
- **Two Blob stores, chosen by key (JEF-51).** `storageAccessFor(key)` (`use-cases/shared/storageAccess.ts`) is the one place that decides: `users/<id>/avatar/…` is `public`, everything else is `private`, so a new kind of file is private unless it opts out. `VercelBlobStorageProvider` sends each key to the store of that access, with that store's token (`BLOB_PUBLIC_READ_WRITE_TOKEN` or `BLOB_PRIVATE_READ_WRITE_TOKEN`). **A missing private token throws; it never falls back to the public store**, so a secret that was not loaded cannot make a document public. `getSignedUrl` throws for a private key for the same reason: only avatars have a storage URL.
- **The client's `put()` must match the store.** A client token is for one store, and `put()` is refused if its `access` differs. `requestUploadUrl` and `requestAvatarUploadUrl` therefore return `access`, and web passes it to `put()` (`blobAccessOf`, which treats anything but `private` as `public` so an older API still works).
